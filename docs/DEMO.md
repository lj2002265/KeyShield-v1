# 钥盾第一版 Demo 说明

版本：v1.0.1。Demo 是真实后端与真实网页组成的本地演示，不是界面视频或静态模型图。下载入口：[GitHub Release](https://github.com/lj2002265/KeyShield-v1/releases/tag/v1.0.1)。

## 三种启动方式

| 方式 | 操作 | 环境要求 |
| 已安装 Windows 版 | 双击桌面 KeyShield Demo | Windows x64，不需 Python |
| Windows 便携包 | 解压 Demo ZIP，双击 Start-Demo.cmd | Windows x64，不需 Python |
| 源码 Demo | 解压源码 ZIP，运行 start-demo.cmd 或 bash start-demo.sh | Python 3.10+，首次安装依赖需联网 |

默认地址为 `http://127.0.0.1:8800`，只有运行程序的本机可以访问。这个地址不是可给远程评审直接访问的公网地址。远程评审应下载程序或源码在自己的电脑启动。

## 建议的十分钟演示流程

1. 展示 GitHub 源码和版本标签，说明产品围绕校园密钥管理、授权和审计展开。
2. 启动程序，注册个人账号；点击获取邮箱验证码，使用页面回显的演示码完成注册，保存恢复密钥。
3. 进入个人空间，点击“演示数据”，展示分类、打码、查看和轮换。样例都是虚构值，不使用真实密钥录屏。
4. 打开审计日志，核对操作记录和哈希链校验提示。
5. 通过 `Admin-Setup.cmd` 或开始菜单管理员入口创建首位管理员，登录该账号。
6. 创建班级管控团队；在另一个浏览器会话注册成员，使用入队码申请加入，由负责人审核。
7. 新增演示托管资源，分类选择 DeepSeek，值可填写 `sk-demo-keyshield-1234567890`，使用代理模式。成员领用后执行不带提示词的演示调用。
8. 检查请求号、用量和日志；移除成员或撤销授权后再次调用，验证权限失效。
9. 成员为已获准资源创建虚拟 Key，展示有效期与额度设置；明文只显示一次，撤销后不能继续使用。
10. 执行 `Verify-Demo.cmd` 或 `KeyShield.exe --verify`，展示隔离检查结果。

学校组织资源的领用在第一版中采用申请后直接授予，团队入队流程才有负责人审核。不要把两者混为“所有调用都需要人工审批”。

## 演示与真实模型的差别

无提示词演示调用不访问模型，结果带有 `demo` 标识，Token 用量为零。它验证权限、用量和审计流程，不生成真实模型回答。发送非空问题会转入真实厂商请求，需自备有效密钥、可用模型和额度，可能产生厂商费用。

虚拟 Key 提供有限的 OpenAI 兼容接口，支持非流式文本；不支持 stream=true、函数调用或多模态。第一版没有自治 Agent、RAG 或 MCP 执行平台，方案书中的后续设计不是当前 Demo 功能。

## 独立验证与结果

`--verify` 会在临时目录启动单独服务并使用随机端口，完成业务回归 64 项和生产安全检查 29 项。检查失败时返回非零退出码；验证不会向真实 SMTP 发信，不会调用付费模型接口。

源码回归也可执行 `python verify_demo.py`。安装版和源码包均不包含原开发环境中的数据库、真实凭据、邮箱授权码或备份。数据路径与故障处理见 [安装说明](INSTALL.md)。
